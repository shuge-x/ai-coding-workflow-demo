# 任务指派 Feature Spec

Status: 教学参考；沿用课程预先给定规则。实现由本次“继续把该做的都做了”的开发授权推进，不声称原生 /to-spec 菜单已执行，也不伪造用户逐条批准记录。

## Problem Statement
项目已有成员和角色，但任务没有负责人，成员无法查看自己负责的任务。

## Solution
Owner / Manager 可以给任务选择一个项目成员、变更或清空负责人；成员可以筛选自己的任务。

## User Stories
1. 作为 Owner，我希望给任务选择项目成员，刷新后保留负责人。
2. 作为 Manager，我希望更换或清空负责人，看到保存成功或失败反馈。
3. 作为 Member，我希望筛选自己负责的任务，同时不能越权修改指派。
4. 作为项目管理者，我希望系统拒绝非项目成员作为负责人。
5. 作为成员，我希望搜索和我的任务筛选可以同时工作，筛选不会改变任务归属。

## Implementation Decisions
任务使用可选的单负责人关系；业务权限从任务所属项目的成员角色判断，服务端再次校验。任务持久化后显示成功，失败保留原值。
基线没有认证系统。本参考使用明确标注的本地教学身份切换器，由服务端读取教学 cookie，不能作为生产认证或安全部署方案。生产接入必须替换为可信会话。

## Testing Decisions
公共指派操作使用独立 SQLite 测试库验证角色、成员资格和取消；浏览器旅程验证 UI → Server Action → 数据持久化 → 刷新与筛选。这两个 seam 由作者在用户授权自主推进的范围内选定，未声称用户逐条批准测试入口。现有标题规范化测试保留。

## Out of Scope
通知、成员邀请、成员移除、生产登录、多租户隔离、拖拽功能。

## Acceptance
- 一个任务最多一个负责人，且负责人必须是当前项目成员。
- Owner 和 Manager 能指派、更换和清空；Member 和非成员请求被服务端拒绝。
- 刷新后负责人一致；我的任务只显示当前教学身份负责的任务，关闭筛选恢复列表。
- 桌面与窄屏可以操作；真实用户 Human Accepted 单独保留。

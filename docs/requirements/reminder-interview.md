# Story 02 到期提醒访谈教学示例

以下对话和候选规则由课程作者编写，用于演示访谈方法；不是本次会话用户的回答，也不是项目已批准需求。实际跟做时，请记录你自己的回答和来源。

实际访谈时一次只提出当前最重要的问题，再根据回答推进。下面保存的是可回顾的完整教学对话。

## 第 1 轮 你说的“相关人员”具体是谁？

Agent 提问：你说的“相关人员”具体是谁？

教学示例回答：本例先考虑主动订阅任务提醒的个人，不把任务负责人作为默认收件人。

为什么继续追问：当前起点没有负责人或收件人关系。先明确“谁需要提醒”，才能讨论身份和订阅如何建立。

记录：教学示例 D01：收件人来自提醒订阅。真实用户是否采用、订阅者身份如何确认，待决定。

## 第 2 轮 “快到期”是到期前提醒，还是已经逾期后的催办？

Agent 提问：“快到期”是到期前提醒，还是已经逾期后的催办？

教学示例回答：本例先讨论截止日前一天的一次提醒；逾期后持续催办另行讨论。

为什么继续追问：提前提醒与逾期催办的触发条件、次数和用户预期不同，需要先确定本轮语义。

记录：教学示例 D02：到期前一次提醒。逾期催办不纳入本例候选范围。

## 第 3 轮 任务的日历截止日期和提醒时刻，应按哪个时区解释？

Agent 提问：任务的日历截止日期和提醒时刻，应按哪个时区解释？

教学示例回答：本例按收件人选择的时区，在任务截止日的前一天 09:00 提醒；没有选择时区时先要求补充。

为什么继续追问：代码把日期输入转成了带时间的值，但这不是业务已经选择的提醒时间或时区。

记录：教学示例 D03：按收件人时区解释日历日期与 09:00。真实用户确认、夏令时异常和修改时区后的行为仍待决定。

## 第 4 轮 任务完成、删除、取消订阅或修改截止日期后怎么办？

Agent 提问：任务完成、删除、取消订阅或修改截止日期后怎么办？

教学示例回答：本例中，完成、删除或取消订阅会取消尚未发送的提醒；修改截止日期后重新计算未发送的计划。已发过一次后能否再发，我还没有决定。

为什么继续追问：状态变化可能让旧计划失效；“重新计算计划”和“允许再发送”是两个问题。

记录：教学示例 D04：失效计划取消，未发送计划重算。已发送任务再次提醒的条件列入未决项。

## 第 5 轮 如果任务没有截止日期，或计划提醒时刻已经过去呢？

Agent 提问：如果任务没有截止日期，或计划提醒时刻已经过去呢？

教学示例回答：本例中，没有截止日期就不安排提醒；新建或改期后计划时刻已经过去，先跳过，不补发历史提醒。

为什么继续追问：可选截止日期与迟到安排都需要明确边界，否则 Agent 会自行选择补发策略。

记录：教学示例 D05：无截止日期不排程；已过提醒时刻的安排跳过。真实采用前仍需确认。

## 第 6 轮 希望通过什么渠道收到提醒？收件地址从哪里来？

Agent 提问：希望通过什么渠道收到提醒？收件地址从哪里来？

教学示例回答：本例先比较邮件渠道。收件地址如何取得、验证和关联订阅者，还没有决定。

为什么继续追问：当前代码没有账户或邮箱关系。渠道偏好不等于已经具备投递条件。

记录：教学示例 D06：邮件为候选渠道；身份、收件地址验证与发送服务选择保持未决。

## 第 7 轮 用户能关闭提醒吗？需要全局免打扰窗口吗？

Agent 提问：用户能关闭提醒吗？需要全局免打扰窗口吗？

教学示例回答：本例允许取消某个任务的提醒订阅；全局免打扰时段以及和 09:00 冲突时如何处理，先列为待讨论。

为什么继续追问：任务级订阅与个人全局偏好不能混成一个开关；尚未讨论的规则应保持可见。

记录：教学示例 D07：任务级关闭。免打扰与全局偏好的覆盖关系保持未决。

## 第 8 轮 投递失败后要重试吗？怎样算这次提醒成功？

Agent 提问：投递失败后要重试吗？怎样算这次提醒成功？

教学示例回答：本例不接受无限重试；次数和间隔仍待决定。发送服务接受了请求，也不代表用户已经收到或阅读。

为什么继续追问：提醒意图、单次投递尝试和用户实际看到消息，是不同的概念与完成状态。

记录：教学示例 D08：失败与重试需显式规则。重试上限、成功判定和失败反馈均待决定。
